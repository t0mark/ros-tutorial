TERMINAL(1)1장Getting Started

터미널과 첫 명령GUI와 CLI · 터미널 열기 · 프롬프트 · 명령어 형식 · man

우분투는 바탕화면에서 마우스로도 쓸 수 있지만, 리눅스를 제대로 다루려면 키보드로 명령어를 입력하는 터미널에 익숙해져야 합니다. 터미널을 열고, 화면에 보이는 프롬프트를 읽는 법부터 시작합니다.

GUI와 CLI

컴퓨터를 조작하는 방식은 크게 두 가지입니다.

GUI (Graphical User Interface)CLI (Command Line Interface)
조작창, 아이콘, 메뉴를 마우스로 클릭명령어를 키보드로 입력
예파일 탐색기에서 폴더를 더블클릭해 열기cd 폴더, ls 입력
장점처음 배우기 쉽고 눈으로 확인하기 편함빠르고 정확함. 여러 작업을 한 줄로 엮거나 자동화할 수 있음
단점반복 작업이 번거롭고, 화면이 없는 환경에서는 쓸 수 없음명령어를 알아야 함

우분투 바탕화면은 GUI이고, 터미널은 GUI 안에서 CLI를 쓰게 해 주는 창입니다. 터미널에 입력한 명령을 읽고 실행해 주는 프로그램을 셸(우분투 기본은 bash)이라고 합니다. 화면이 없는 서버나 로봇에 들어가는 작은 컴퓨터는 CLI로만 다루는 경우가 많고, 같은 일을 GUI보다 빠르게 할 수 있어서 리눅스 사용자는 대부분 CLI를 주로 씁니다.

# 같은 일: 홈에 work 폴더를 만들고 memo.txt 를 복사해 넣기
# GUI → 파일 앱 열기 → 홈 → 우클릭 → 새 폴더 → 이름 입력 → memo.txt 찾기 → 복사 → work 열기 → 붙여넣기
$ mkdir ~/work && cp memo.txt ~/work      # CLI

터미널 열기

  • 단축키 Ctrl+Alt+T
  • 또는 화면 왼쪽 아래 앱 표시 버튼(점 9개)을 누르고 "터미널"(Terminal)을 검색
  • 터미널을 연 상태에서 우분투 화면 왼쪽 세로 막대(독, Dock)에 생긴 터미널 아이콘을 우클릭하고 즐겨찾기에 추가를 누르면, 터미널 아이콘이 그 막대에 계속 남아 다음부터 한 번에 열 수 있습니다.

터미널 창 안에서 복사·붙여넣기는 Ctrl+C/V가 아니라 Ctrl+Shift+C/V입니다. 터미널에서 Ctrl+C는 "실행 중인 명령 중단"이라는 다른 뜻으로 쓰이기 때문입니다.

프롬프트 읽기

root@ubuntu:/home/student#
# 관리자(root)로 바꾸면 사용자명이 root, 끝이 # 로 바뀜

문서나 예제에서 명령 앞에 $가 있으면 일반 사용자로, #이 있으면 관리자 권한으로 실행하라는 뜻입니다. $, # 자체는 입력하지 않습니다.

명령어의 형식

$ ls                # 명령어만
$ ls -l             # 옵션
$ ls -l /etc        # 옵션 + 인자
이름을 알면 외우기 쉽다리눅스 명령어와 옵션은 대부분 영어 단어를 줄인 것입니다. 이 자료에서는 명령어마다 아래처럼 원래 이름을 붙여 두었고, 주황색 굵은 글자가 약자에 쓰인 글자입니다.
lslist-llong-aallbashBourne Again Shell
대소문자리눅스는 대소문자를 구분합니다. ls -r과 ls -R은 다른 옵션이고, File.txt와 file.txt는 다른 파일입니다.

확인 문제

터미널, 셸, CLI는 각각 무엇인가?

CLI는 명령어를 입력해 컴퓨터를 다루는 방식, 터미널은 그 명령을 입력하고 결과를 보는 창, 셸(bash)은 입력한 명령을 해석해 실행하는 프로그램입니다.

프롬프트가 root@web01:/var/log#이다. 사용자, 호스트, 현재 위치는?

사용자 root(관리자), 호스트 web01, 현재 위치 /var/log.

긴 파일 이름을 정확히 입력하기 귀찮다. 어떻게 하나?

앞 몇 글자만 치고 Tab을 누릅니다.

왜 사용자 계정이 필요할까

예전에는 컴퓨터가 방 하나를 채울 만큼 크고 매우 비쌌습니다. 그래서 기업이나 대학은 컴퓨터를 한 대만 들여놓고, 여러 사람이 각자 자리의 단말기(화면과 키보드만 있는 장치)를 그 컴퓨터에 연결해 동시에 나눠 썼습니다. 리눅스의 뿌리인 유닉스(Unix)는 처음부터 이런 환경을 위해 만들어졌습니다.

한 컴퓨터를 여러 사람이 함께 쓰려면 정해야 할 것이 생깁니다.

  • 누구인가: 로그인한 사람이 누구인지 구분해야 합니다 → 사용자 계정과 비밀번호
  • 어디에 저장하나: 각자 파일을 둘 자기만의 공간이 필요합니다 → 홈 디렉터리 (/home/사용자명)
  • 무엇을 할 수 있나: 남의 파일을 지우거나 시스템을 망가뜨리지 못하게 해야 합니다 → 권한(6장)과 관리자 계정
  • 함께 쓰는 것은: 같은 팀끼리는 파일을 같이 써야 합니다 → 그룹

지금은 컴퓨터가 싸져서 한 사람이 한 대씩 쓰지만, 이 구조는 그대로 남아 여전히 쓸모가 있습니다. 연구실 서버나 클라우드 서버는 지금도 여러 사람이 계정을 나눠 접속해서 씁니다(12장 SSH). 로봇에 올린 컴퓨터에도 팀원 여럿이 원격으로 접속합니다. 혼자 쓰는 우분투에서도 평소에는 권한이 제한된 내 계정으로 작업하고 꼭 필요할 때만 sudo로 관리자 권한을 빌려 쓰기 때문에, 실수로 시스템 파일을 지우는 사고를 막을 수 있습니다.

Python 파일 실행하기

Python 파일을 실행하는 방법은 두 가지입니다.

print("Hello, Linux!")
① 인터프리터에 파일을 넘기기

실행되는 프로그램은 python3이고, hello.py는 그 프로그램이 읽는 파일일 뿐입니다. 그래서 읽기 권한(r)만 있으면 됩니다.

② 파일 자체를 실행하기

파일을 프로그램처럼 직접 실행하려면 실행 권한(x)과 첫 줄의 #!(셔뱅, shebang)이 둘 다 필요합니다.

+xexecute 권한 추가#!shebang (sharp # + bang !)envenvironment.shshell script
#!/usr/bin/env python3
print("Hello, Linux!")
  • 셔뱅은 파일 맨 첫 줄에 #! 다음에 "이 파일을 어떤 프로그램으로 실행할지"를 적은 것입니다. ./hello.py를 실행하면 실제로는 /usr/bin/env python3 ./hello.py가 실행됩니다.
  • /usr/bin/env python3은 환경 변수 PATH(8장)에서 python3을 찾아 실행하라는 뜻입니다. #!/usr/bin/python3처럼 경로를 직접 적어도 됩니다.
  • 셔뱅이 없으면 bash가 파일을 셸 명령어로 읽으려 해서 syntax error near unexpected token 같은 오류가 납니다.
  • 앞의 ./는 "현재 디렉터리에 있는 이 파일"이라는 뜻입니다. 현재 디렉터리는 PATH에 없기 때문에 hello.py만 입력하면 command not found가 나옵니다 (PATH는 8장).
  • 셸 스크립트(.sh)도 같은 원리이며, 첫 줄에 #!/bin/bash를 씁니다.

USB를 꽂으면 운영체제가 장치를 인식하고, udev라는 장치 관리 프로그램이 /dev에 장치 파일을 만들면서 이름, 소유자, 그룹, 권한을 정합니다. 뽑으면 파일을 지웁니다. 위에서 /dev/ttyUSB0가 dialout 그룹으로 만들어진 것도 udev의 규칙 때문입니다.

운영체제장치 인식, 드라이버 연결

/dev/ttyUSB0이름·그룹·권한 결정

규칙은 /etc/udev/rules.d/에 .rules 파일로 직접 추가할 수 있습니다. 가장 흔한 용도는 고정된 이름 붙이기입니다. 장치가 여러 개면 꽂는 순서에 따라 ttyUSB0과 ttyUSB1이 바뀔 수 있는데, 제조사·제품 ID로 장치를 골라 항상 같은 이름의 링크를 만들어 두면 프로그램에서 그 이름만 쓰면 됩니다.

# lsusb 에서 본 ID 10c4:ea60 인 장치에 /dev/lidar 링크를 만들고, 누구나 읽고 쓰게
SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60", SYMLINK+="lidar", MODE="0666"
$ sudo nano /etc/udev/rules.d/99-lidar.rules          # 위 한 줄 작성
$ sudo udevadm control --reload-rules                 # 규칙 다시 읽기
$ sudo udevadm trigger                                # 연결된 장치에 적용 (또는 다시 꽂기)
$ ls -l /dev/lidar
lrwxrwxrwx 1 root root 7 Oct  5 10:20 /dev/lidar -> ttyUSB0   # 심볼릭 링크(4장)
$ udevadm info -a -n /dev/ttyUSB0 | grep idVendor     # 규칙에 쓸 속성 찾기

==는 "이 조건과 같으면", =와 +=는 "이렇게 설정하라"는 뜻입니다. MODE="0666"은 6장의 8진수 권한입니다.

STDIN(3)7장Input and Output

입력과 출력입력 → 처리 → 출력 · stdin · stdout · stderr · > · >> · 2> · 2>&1 · < · | · tee · /dev/null

컴퓨터든 명령어 하나든, 모두 "무언가를 받아서(입력) 처리하고 결과를 내보내는(출력)" 구조입니다. 이 구조를 알면 명령의 결과를 파일에 저장하거나, 오류만 따로 모으거나, 여러 명령을 이어 붙이는 방법이 자연스럽게 이해됩니다.

컴퓨터의 기본 구조: 입력 → 처리 → 출력

  • 입력(Input): 바깥에서 컴퓨터 안으로 들어오는 데이터. 키보드로 친 글자, 센서 값, 읽어 들인 파일 내용.
  • 처리: CPU가 메모리에 올린 데이터를 계산합니다. 프로그램이 하는 일이 여기입니다.
  • 출력(Output): 처리 결과를 바깥으로 내보내는 것. 화면에 글자 표시, 모터 회전, 파일에 쓰기.

명령어 하나도 똑같습니다. sort는 줄들을 입력받아 정렬(처리)하고 그 결과를 출력합니다. 입력과 출력을 줄여서 I/O라고 부릅니다.

출력 재지정: > 와 >>

화면으로 가던 1번(표준 출력)을 파일로 돌립니다. >는 1>을 줄여 쓴 것입니다.

$ ls -l > list.txt          # 새로 쓰기: list.txt 가 있으면 내용을 지우고 덮어씀
$ date >> list.txt          # 덧붙이기: 기존 내용 뒤에 추가
$ echo "첫 줄" > memo.txt     # 파일을 간단히 만들기
$ cat > memo2.txt           # 키보드로 내용 입력 → Ctrl+D 로 입력 끝 → 파일 생성
$ cat a.txt b.txt > ab.txt  # 두 파일을 이어서 새 파일로 (cat = concatenate)
주의>는 경고 없이 기존 내용을 지웁니다. 설정 파일에 한 줄 추가하려다 >를 쓰면 파일 전체가 사라집니다(8장 .bashrc 참고). 또 sort a.txt > a.txt처럼 읽는 파일과 쓰는 파일이 같으면, 명령이 읽기 전에 파일이 먼저 비워져 빈 파일이 됩니다.

오류 재지정: 2>, 2>&1, /dev/null

2번(표준 오류)을 돌리려면 번호를 앞에 붙입니다.

$ ls /etc /nothing > out.txt 2> err.txt   # 결과와 오류를 각각 다른 파일로
$ cat err.txt
ls: cannot access '/nothing': No such file or directory
$ ls /nothing 2>> err.txt                   # 오류를 기존 파일 뒤에 덧붙이기
$ ls /etc /nothing > all.txt 2>&1          # 오류도 결과와 같은 곳(all.txt)으로
$ ls /etc /nothing &> all.txt              # 위와 같음 (bash 줄임 표기)
$ find / -name "*.rules" 2> /dev/null       # 권한 오류는 버리고 결과만 보기
  • 2>&1은 "2번을 1번이 지금 가는 곳으로 보내라"는 뜻입니다. &1의 &는 "1이라는 이름의 파일"이 아니라 "1번 통로"라는 표시입니다.
  • 순서가 중요합니다. > all.txt 2>&1은 1번을 파일로 돌린 다음 2번을 따라가게 하므로 둘 다 파일로 갑니다. 2>&1 > all.txt로 쓰면 2번은 그 순간 1번이 가던 화면으로 가고, 1번만 파일로 갑니다.
  • /dev/null은 쓰는 내용을 전부 버리는 특수 장치 파일입니다("블랙홀"). 필요 없는 출력이나 오류를 없앨 때 씁니다.
nullnull (아무것도 없음)&>1번과 2번을 모두 재지정

입력 재지정: < 와 <<

0번(표준 입력)을 키보드 대신 파일에서 읽게 합니다.

$ wc -l story.txt           # 파일 이름을 인자로 주면 wc 가 직접 파일을 엶
38 story.txt
$ wc -l < story.txt         # 셸이 파일을 열어 0번에 연결 → wc 는 이름을 모름
38
$ sort < names.txt > sorted.txt   # 입력과 출력을 동시에 재지정
$ wc << END                 # here document: END 가 나올 때까지의 줄을 입력으로
> hello !
> word count
> END
2 4 20

키보드로 입력할 때 Ctrl+D는 "입력이 끝났다(EOF)"는 신호입니다. cat > 파일이나 sort를 인자 없이 실행했다가 멈춘 것처럼 보이면, 프로그램이 0번(키보드)에서 입력을 기다리는 중입니다.

EOFEnd Of File

파이프: 명령의 출력을 다음 명령의 입력으로

명령1 | 명령2는 명령1의 1번(출력)을 명령2의 0번(입력)에 직접 연결합니다. 중간 파일 없이 작은 명령들을 조립해서 원하는 결과를 만드는 것이 리눅스를 쓰는 기본 방식입니다.

$ ls | wc -l                          # 현재 디렉터리의 파일 개수
$ ps -ef | grep bash                  # 프로세스 목록에서 bash 만 (9장)
$ history | tail -5                   # 최근 명령 5개
$ cat story.txt | grep pig | wc -l    # pig 가 들어간 줄 수: 세 단계 조립
$ ls /etc | tee etc-list.txt | wc -l  # tee: 화면(다음 명령)과 파일에 동시에
$ ls /etc /nothing 2>&1 | wc -l       # 오류 줄까지 함께 넘기기
|pipe (배관)teeT자 배관 (한 흐름을 둘로 나눔)whowho (누가 접속해 있나)sortsort (정렬)
파이프는 1번만 넘긴다파이프로 넘어가는 것은 표준 출력뿐입니다. 오류(2번)는 여전히 화면으로 나옵니다. 오류까지 다음 명령에 넘기려면 2>&1 |로 씁니다.

>와 >>의 차이는?

>는 기존 내용을 지우고 새로 쓰고, >>는 기존 내용 뒤에 덧붙입니다.

0 표준 입력(키보드), 1 표준 출력(화면), 2 표준 오류(화면).

셸 설정 파일 .bashrc

~/.bashrc는 홈 디렉터리에 있는 bash의 개인 설정 파일입니다. 이름이 .으로 시작하는 숨김 파일이라 ls -a로만 보입니다. 내용은 셸 명령어를 한 줄씩 적어 둔 것이고, 새 터미널을 열 때마다 bash가 이 파일을 처음부터 끝까지 자동으로 실행합니다. 그래서 매번 입력하기 귀찮은 설정을 여기에 적어 두면 터미널을 열 때마다 적용됩니다.

# 별명
alias ll='ls -l'
alias rm='rm -i'                 # rm 을 항상 확인하며 지우도록
# 환경 변수 설정 (명령을 찾을 디렉터리 추가)
export PATH=$PATH:~/bin
# 기억할 history 개수
HISTSIZE=2000

파일 끝에 한 줄을 덧붙일 때는 재지정 >>를 쓰면 됩니다. 길게 고칠 때는 편집기(13장)로 엽니다.

$ echo "alias ll='ls -l'" >> ~/.bashrc   # 반드시 >> (추가)
$ tail -3 ~/.bashrc                      # 잘 들어갔는지 확인
$ nano ~/.bashrc                         # 편집기로 직접 고치기
주의>로 쓰면 .bashrc의 기존 내용이 전부 지워집니다. 우분투가 기본으로 넣어 둔 설정(컬러 프롬프트, 기본 별명 등)까지 사라지니 꼭 >>를 쓰세요. 고치기 전에 cp ~/.bashrc ~/.bashrc.bak으로 백업해 두면 안전합니다.

source: 설정을 지금 바로 적용하기

.bashrc를 고쳐도 이미 열려 있는 터미널에는 반영되지 않습니다. 파일은 터미널을 열 때 한 번만 읽기 때문입니다. 새 터미널을 열거나, source로 지금 쓰는 셸에서 파일을 다시 실행합니다.

$ echo "alias ll='ls -l'" >> ~/.bashrc
$ ll
ll: command not found        # 아직 현재 셸은 모름
$ source ~/.bashrc             # 또는 . ~/.bashrc

bash ~/.bashrc 로는 안 되는 이유bash 파일이나 ./파일로 실행하면 셸이 자식 셸(새 프로세스, 9장)을 만들어 그 안에서 실행합니다. 별명과 변수는 자식 셸에만 생겼다가 실행이 끝나면 함께 사라집니다. source는 자식을 만들지 않고 지금 셸이 직접 실행하므로 설정이 남습니다.

묶기와 압축은 다르다

tar는 여러 파일을 하나로 묶기만 합니다(아카이브). 복원에 필요한 이름·크기·권한 정보가 더해지므로 결과 파일은 원본들의 합보다 오히려 조금 큽니다. 크기를 줄이는 것은 gzip 같은 압축 프로그램의 일입니다. 그래서 흔히 보는 .tar.gz는 "tar로 묶고 gzip으로 압축한 파일"입니다.

네트워크 기본 개념

  • IP 주소: 네트워크에서 컴퓨터를 구분하는 번호 (192.168.0.10). 127.0.0.1은 항상 "나 자신"(localhost)입니다.
  • 공인 IP / 사설 IP: 인터넷 전체에서 유일한 주소 / 공유기 안처럼 내부에서만 쓰는 주소 (192.168.x.x, 10.x.x.x)
  • 도메인 이름: IP에 붙인 이름. DNS가 이름을 IP로 바꿔 줍니다. 내 컴퓨터만의 변환표는 /etc/hosts.
  • 포트: 한 컴퓨터 안에서 어떤 서비스와 통신할지 구분하는 번호(0~65535). SSH 22, FTP 21, HTTP 80. 전체 주소는 IP:포트.
  • TCP / UDP: TCP는 연결을 맺고 데이터가 빠짐없이 순서대로 도착하도록 보장합니다(웹, SSH). UDP는 보장이 없는 대신 단순하고 빠릅니다(실시간 방송).

다른 리눅스 컴퓨터에 원격 접속하기: SSH

지금까지는 내 컴퓨터에 설치한 우분투의 터미널에서 명령을 입력했습니다. 실제 현장에서는 데이터센터나 클라우드에 있는 서버를 다루는 일이 많은데, 서버에는 보통 모니터도 바탕화면도 없습니다. 그래서 네트워크로 서버에 접속해 내 터미널에서 서버의 셸을 쓰는 방법을 씁니다. 이때 쓰는 것이 SSH(Secure Shell)입니다.

  • 주고받는 내용(비밀번호 포함)이 모두 암호화됩니다.
  • 서버 쪽에서는 sshd라는 프로그램이 22번 포트에서 접속을 기다립니다.
  • 접속하면 프롬프트의 호스트 이름이 서버 이름으로 바뀝니다. 이후 입력하는 명령은 모두 서버에서 실행됩니다.
